# Research 结果展示与当前产品稳定性验收

## 本次范围

- 指标卡（ROE、净利率、资产周转率、权益乘数及较上年变化）。
- 各年输入、平均余额、计算结果、单位与来源表格。
- 同一指标的年度对比柱状图。
- 可切换年份的杜邦分解图及 Evidence 联动。
- 杜邦新版任务支持 3～5 年，默认 5 年；历史两年任务继续按原合同读取/恢复。
- 不做趋势图、饼图、桑基图、瀑布图或图表编辑器。

## 执行顺序

1. 扩展有界多期财务 Scope、数据准备、计算与核验；不扩大历史任务权限。
2. 从已有报告版本与正式 Evidence 构建结构化结果视图，不解析 Markdown 数字、不建立第二套执行状态。
3. 复用安全图表能力，补齐表格渲染、四项展示和来源入口；缺失/未核验状态不冒充成功。
4. 建立当前产品 10 场景 × 5 次验收合同与可执行入口，覆盖 L2 技能、Research 和数据不足边界。
5. 执行真实调用与工程回归，保存所有失败及修复后新批次，核对结果数据、终态、预算和证据。

## 证据边界

旧 `sec-release-evidence-v1` 的 10 场景 × A0～A4 是能力对照，不是当前产品模式的重复稳定性测试。
新的 50 次验收独立记录，不覆盖旧结果、不伪造旧矩阵通过；模型/API 调用次数也不等于 Run 数。
新闻 Provider 尚需使用条款审批，未经授权的新闻正向检索不纳入已通过声明。
权限、取消与持久恢复同时保留独立的受控故障测试，不能用普通 Run 完成率代替。

## 完成标准

- 新旧 Scope/任务合同、越权与口径校验、结果版本一致性通过测试。
- 四项结果展示真实读取同一结果，前端不重算财务公式；刷新不重新执行 Research。
- API 契约、迁移（若需要）、类型、格式、安全、单元/集成/浏览器检查通过。
- 当前产品场景精确覆盖 50 个正式 Run，逐项报告验收结论；未通过的批次仍保留。

## 问题二：当前场景合同

场景是针对本项目编写的回归集，不是外部 benchmark；所有重复调用都使用同一代码、配置与场景快照。

| 场景 | 每批次数 | 检查 |
| --- | --- | --- |
| L2 财报片段解释 | 5 | 自主选择对应 Skill、无多余工具、原文数值与解释要点 |
| L2 比较口径 | 5 | 对应 Skill、指出收购口径差异，不进行增幅计算 |
| L2 缺少片段 | 5 | 请求补充原文，不伪造财报 |
| L2 非金融问题 | 5 | 不加载无关 Skill |
| Research 年度收入核验 | 5 | 正式 XBRL、FY2025 收入锚点、独立核验 |
| Research 净利率 | 5 | 两项取数、正式计算及 36.1460% 数值锚点 |
| Research 三年杜邦 | 5 | 3 份计算、12 行逐年输入/结果/变化及来源 |
| Research 四年杜邦 | 5 | 4 份计算、12 行逐年输入/结果/变化及来源 |
| Research 五年杜邦 | 5 | 5 份计算、12 行逐年输入/结果/变化及来源 |
| 截止时点早于申报 | 5 | 精确的 `sec_snapshot_not_visible` 拒绝，无未来 Evidence |

满分为 45 次正常完成与 5 次预期拒绝，不是 50 份成功报告。供应商故障不能算作边界拒绝。
DuPont oracle 独立使用官方年度输入和 Decimal 公式，不把生产计算器返回值当作正确答案；L2 的自动判断是工具选择及文本要点检查，不代表开放问答的完整语义质量 benchmark。
每次记录 Run/Job ID、真实模型尝试与完成次数、Token/费用/Step/截止时间、唯一终态、工具观察 hash、核验结果及可视化结果。
费用为系统 route 的计费估算；按次收费网关的实际扣费不由该值证明。
Token 统计仅包含有可信用量回执的模型响应；失败响应可能没有可核对的 Token 用量。模型尝试次数单独记录，不将账面零费用解释为免费调用。
业务通过率与运行控制正确性分别报告：供应商故障被正确记录为一个失败终态，并不意味着该业务场景通过。完整失败批次与恢复后的重复批次均保留。

## 执行入口

先用前端或 `dupont_live_runner.py --years 5` 完成五份官方年报的数据准备，再执行：

```powershell
uv run --locked python apps/backend/tests/product_stability_runner.py --workspace-id <workspace UUID> --user-id <owner UUID> --knowledge-base-id <已准备的 KB UUID> --industry-id <行业 UUID> --output .data/evals/product-stability-final-01
```

输出目录必须不存在；脚本不恢复旧批次，不自动重试失败 Run。`--case <场景 ID> --repetitions 1` 只用于诊断，永远不算完整验收。
正式批次运行期间不要修改 `apps/`、`packages/`、锁文件或场景；源代码哈希变化会使批次失效。
脚本读取 `.env`，验证现有 owner 身份，使用真实模型、官方 SEC 快照和正常服务/Job delivery，不绕过工具或核验层。
同一开发数据库上不要同时运行受控浏览器驱动：真实 dispatcher 会发布其待执行 Outbox，而该驱动要求独占认领 pending 消息。浏览器检查与此批次顺序执行。

失败诊断批次保存在 `.data/evals/product-diagnostic-*`、`product-probe-*`，正式报告单独记录修复后冻结批次，不能将它们拼成一次 50/50。

## 真实调用定位的修复

- 官方 2021 年 inline XBRL 存在 269 字符 context ID；解析域、存储列与计算证据一致支持 512，locator 支持 1024，保留原始标识。
- 多年授权窗口同时应用于取数和计算时重新解析源事实；只改取数窗口会导致早期年度无法计算。
- 五年共 22 个唯一事实；Tool、Evidence 域与数据库正规化序号边界一致调整为 32。
- 计算回执曾反复携带完整输入和源元数据，挤掉最早的年度取数结果；模型投影保留必要输入、期间和结果，原始观察完整存储。
- 普通指标工具的“多个指标不筛选”说明与 16 条返回上限冲突，改为每个已知概念单独查询。
- required-tool 进度原先在首次取数后只暴露计算工具，阻止补取分母；当前阶段允许继续调用前置工具，仍禁止越过未完成阶段、提前 final、原样重复调用或超预算。
- JSON 模式明确要求原始 JSON 对象；带围栏、额外字段或不符合当前阶段的响应仍由原严格 Schema 拒绝。
- 备用模型诊断发现初次 Research Job 误用普通对话的 300 秒软超时，早于研究预算；新建与恢复共用 1,650/1,800 秒软硬限额，给最大 1,500 秒 Run 预算留出终态写入时间。普通对话保持 300/330 秒，不能靠延长研究限额绕过 Run 自身预算。
- 稳定性执行器在后台交付失败时仍采集持久化 Trace，保留失败结论，不静默重放或丢弃模型尝试信息。

边界修复保留原有 Run/Event/Checkpoint、权限与幂等路径，不增加第二套执行状态。数据库迁移与前后端代码应一起部署。

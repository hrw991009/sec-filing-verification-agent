## 3. 发布阻断项

进入 `RC_READY` 前至少需要关闭以下类别，且不能删除原分母或降低阈值：

- 完成 50 个生产 Runtime common-case runs，保存 Run/Trace/Evidence/Calculation/最终数据库
  状态，并计算 Recall@5、Citation、拒答、安全和成本延迟指标；
- 执行公开集 prediction、受控 live model suite 每项至少 3 次，并取得合规 Provider 凭据；
- 执行 12/12 staging 恢复与上一不可变镜像回滚，恢复率 100%，重复副作用、数据损失和
  越权写均为 0；
- 完成无 interception 的中文 SEC 浏览器全链、真实大体积 SEC bulk 运行、table
  locator/Citation 可解析证据；
- 处理 6 组历史凭据候选，完成外部数据与 source document 权利复核、中文抽样签字和最终
  owner acceptance。

完整清单以 [发布就绪合同](../release-readiness.md) 和机器报告为准；本文件不得手工覆盖其状态。

## 4. 产品声明边界

产品范围仅为 SEC 公开披露事实核验、确定性计算、变更监控和可审计引用，不提供实时行情、
预测、估值、目标价、荐股、交易动作、法定审计、法律或税务意见。任何后续候选说明都必须
标明 evidence layer、数据/模型/Tool/Prompt 版本、执行日期、分母和限制。

## 5. 恢复与回滚

正式候选必须按 [Day 10 恢复与回滚 Runbook](../runbooks/day-10-release-recovery.md) 在隔离的
staging/disposable 环境执行。数据库和对象存储恢复优先，Milvus/Elasticsearch 只从已授权的
PostgreSQL/MinIO 事实重建；回退只允许使用已记录 digest 的上一不可变镜像。不得用
`docker compose down --volumes` 代替恢复演练，也不得把 Runbook 命令存在当作执行成功。

## 6. 候选提升条件

只有机器报告同时满足 `release_decision=rc_ready`、`rc_ready=true`、全部 D10-01～D10-08 为
`complete`、blocker=0、pending external gate=0，且对应合并提交的 main CI 与 owner acceptance
都有证据时，项目所有者才能将本草案改为候选说明并创建标签。Codex 不自动 commit、push、
merge 或打标签。
